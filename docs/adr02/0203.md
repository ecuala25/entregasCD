# Ejercicio 3: Ciclo de vida en la practica

## 1. ¿Qué modelo de ciclo de vida recomendarías y por qué? (Cascada o Iterativo)

Yo recomendaría un ciclo de vida iterativo debido a la necesidad de Feedback. Ya que los clientes piloto darían feedback que puede requerir añadir o modificar funciones en cada iteración. EN el modelo Cascada esto no es posible ya que no hay feedback hasta practicamente el final del proceso, por lo que no sería nada práctico.

## 2. ¿Qué metodología aplicarías? (Métrica v3 o Ágil) Justifica la respuesta.

Aplicaría una metodología Ágil. Debido a que se necesita colaboración y feedback continuo, la metodología Ágil es más apropiada. La métrica v3 sería mejor para un caso que necesitase ser auditable y normalizado, con un modelo en cascada, para este caso sería contraproducente.

## 4. Para la clase Envío, describe cómo debería comportarse la operación de actualizar el estado.

Primero recibe el dato: el nuevo estado del envío. EL cual solo podrá tener uno de estos valores: "EN_ALMACÉN", "EN_REPARTO", "ENTREGADO" o "DEVUELTO".

1. Comprobará si el valor recibido es válido, es decir, si es uno de los 4 especificados antes.
2. Si es válido se sustituye el valor anterior por el nuevo, después se confirma el cambio.
3. Si no es válido, no se realiza ningún cambio y la operación indica que no se ha podido realizar la actualización del estado.
